# brewery — Homebrew compatibility list

Target version verified: **Homebrew 7.0.11** (local install reports `7.0.11-47-g9226bdf`, a `main`-branch git build; it was `7.0.11-36-g7411197` at the start of this research session — brew auto-updated itself mid-session, see "Auto-update interference"). Date: **2026-10-29**. Docs: docs.brew.sh as of the same date.

## The key architectural fact

**Homebrew has no stable public API.** Supported integration is:

1. **The CLI** (`brew …`) with `--json` output where available. The docs state JSON query output carries "less risk of being broken due to Homebrew code changes" than external Ruby commands, and warn "Homebrew can't guarantee that external commands will continue to work."
2. **Documented `HOMEBREW_*` environment variables** (documented in the Manpage's ENVIRONMENT section — the old standalone EnvVariables page no longer exists; `https://docs.brew.sh/EnvVariables` returns 404).
3. **The on-disk layout** (`$(brew --prefix)/Cellar`, `Caskroom`, `opt`, `var`, `Library/Taps`) — stable in practice but not a contractual API.

Internal Ruby classes are explicitly unstable: "Public APIs require the full deprecation lifecycle before removal. Internal APIs do not require a deprecation period." A GUI must not link against `Library/Homebrew` Ruby code.

JSON schema stability (from docs.brew.sh/Querying-Brew, quote): "fields may be added to the schema as needed without incrementing the schema. Any significant breaking changes will cause a change to the schema version." The schema "is not currently documented outside of the code in `formula.rb`". `formulae.brew.sh` mirrors the same JSON via a "documented JSON API" (e.g. `https://formulae.brew.sh/api/formula/ace.json`) — useful read-only mirror for a GUI that doesn't need local state.

## Capabilities

### 1. Inventory: installed formulae / casks / versions
- GUI feature: package list view, badge counts.
- Commands: `brew list --formula`, `brew list --cask`, `brew list --versions` (observed output `ace 8.0.8`), `brew list --pinned` (plain; verified, empty here), `brew list --full-name`, `--tree`, `--reverse` (manpage — UNVERIFIED locally), and the JSON path: `brew list --json --versions`.
- Richer JSON: `brew info --json=v2 --installed` (docs-recommended for "formula and cask inventory, including each installed formula keg's `sbom` path"). Each installed keg carries an SBOM at `$(brew --prefix)/Cellar/<name>/<ver>/sbom.spdx.json` (observed in `installed[].sbom`) — see docs `/Homebrew-Inventory-and-SBOM` for fleet/SBOM framing.
- Gotchas: `list --json` refuses without `--versions`, with named args, or without `jq`. `brew cask` as a subcommand no longer exists (use `brew list --cask` / `brew info --cask`); the old separate cask CLI died in the 3.x era and 7.x shows no trace of it (docs Deprecating page: deprecated flags are hidden from `--help` and eventually raise errors — UNVERIFIED for `brew cask` specifically, but local install has no `cask` command).

### 2. Search / info / deps / uses / leaves
- GUI feature: catalog browser, dependency graph, "why is this installed?".
- Commands: `brew search TEXT|/regex/` (`--formula`/`--cask`, `--desc` verified via usage); `brew info [pkg]` / `brew info --json=v2`; `brew deps [pkg]` with `--installed`, `--topological`, `--graph`, `--dot`, `--annotate`, `--tree`, `--union`, `--full-name`, `--include-build/optional/test`, `--skip-recommended`, `--missing`, `--for-each`, `--os`, `--arch`, `--brewfile` (all observed in usage output); `brew uses` with `--recursive`, `--installed`, `--missing`, `--formula`, `--cask`; `brew leaves [--installed-on-request|--installed-as-dependency]` (verified).
- Machine-readable: only `info` has JSON. **`deps`/`uses`/`leaves`/`search` have no JSON in 7.0.11.** Workarounds: parse plain line output; for forward deps use `installed[].runtime_dependencies` in `info --json=v2` (actual runtime deps, matches `brew linkage` semantics); reverse-dep a local set by inverting `dependencies`/`runtime_dependencies` across installed packages.
- Gotchas: docs (manpage) state `deps` with no options on installed formulae shows *actual runtime dependencies*, which may differ from declared ones. `search` hits both formulae and casks and may return formula names that are not installable from API taps. GitHub-API-backed search can be rate-limited; `HOMEBREW_GITHUB_API_TOKEN` raises limits, `HOMEBREW_NO_GITHUB_API=1` blocks it.

### 3. Outdated & upgrade flows
- GUI feature: "updates available" badge, selective upgrade UI.
- Commands: `brew outdated --quiet` (names only), `--verbose` (version detail), `--formula`/`--cask`, `--json` / `--json=v2`, `--fetch-HEAD`, `--greedy` / `--greedy-latest` / `--greedy-auto-updates`, `--vulnerable` / `--severity low|medium|high|critical` / `--minimum-version` (all from manpage; `--greedy`/`--verbose` verified locally).
- Upgrade: `brew upgrade [pkgs…]` — flags: `-g/--greedy`, `--greedy-latest`, `--greedy-auto-updates`, `--fetch-HEAD`, `--vulnerable`, `--severity`, `--minimum-version`, `-n/--dry-run` (verified as documented flag), `-f/--force`, `--overwrite`, `--no-quit` (don't quit running cask apps), `--skip-cask-deps`, `--require-sha`, `--[no-]binaries`, `-y/--no-ask`. `HOMEBREW_UPGRADE_GREEDY`, `HOMEBREW_UPGRADE_GREEDY_CASKS`, `HOMEBREW_NO_UPGRADE_AUTO_UPDATES_CASKS`, `HOMEBREW_NO_UPGRADE_QUIT_CASKS` env equivalents.
- Semantics to surface in UI: pinned packages are skipped by upgrade; `version :latest` and `auto_updates true` casks are skipped unless `--greedy` (`HOMEBREW_UPGRADE_GREEDY`); deprecated packages proceed with a warning; disabled packages fail with an error. Pinned casks with `auto_updates true` may self-update outside Homebrew (verified pin usage text).
- **Tap-package outdated policy (shipped 2026-10-30):** the core manifest has no tap entries (§env snapshot), so manifest-miss rows fall back to the installed-info JSON's own fields: the `outdated` boolean — a pure version compare, not suppressed by pinning (`outdated = installed && formula.outdated?` in `cmd/info.rb`) — and the definition's latest-known version (formula `versions.stable`, cask `version`; live-verified awscli 2.39.2 while installed 2.39.1, agterm 0.39.1 while installed 0.38.1 — `versions.stable` is latest, not installed). The installed-newer guard is checked BEFORE the boolean (never arrow to an older version), self-updating casks still follow the greedy setting, and rows without info JSON stay `.unknown`. Core rows keep manifest semantics.
- Vulnerability-aware updating: `brew outdated --vulnerable --json=v2` (docs-recommended pairing) and `brew vulns --json` (docs `/Homebrew-Vulnerability-Management`). UNVERIFIED locally (network scan).
- Auto-update interference: **`brew outdated` triggered a full self-update mid-session on this machine** ("==> Auto-updating Homebrew…" then version bump). For deterministic GUI queries set `HOMEBREW_NO_AUTO_UPDATE=1`; tune with `HOMEBREW_AUTO_UPDATE_SECS` (default 86400), `HOMEBREW_API_AUTO_UPDATE_SECS` (default 450), `HOMEBREW_AUTO_UPDATE_QUIET`, `HOMEBREW_FORCE_API_AUTO_UPDATE`. **Related verified behavior (2026-10-29, git build 7.0.11-47):** with the cached API package manifest stale well past `HOMEBREW_API_AUTO_UPDATE_SECS`, `brew info --json=v2 --installed` does *not* refetch it — neither under `NO_AUTO_UPDATE=1`, nor with `HOMEBREW_API_AUTO_UPDATE_SECS=0`, nor with `NO_AUTO_UPDATE` unset and `HOMEBREW_AUTO_UPDATE_SECS=100000`. Consequence for the GUI: query commands alone cannot keep "latest version" data fresh; badge freshness needs its own mechanism (exact knob behavior on a *released* brew UNVERIFIED — tested on the git build).

### 4. Install / reinstall / bottles vs source builds (mutating)
- GUI feature: install/reinstall buttons, "install from source" toggle.
- Commands: `brew install [pkg]` with `-s/--build-from-source`, `--HEAD`, `-f/--force`, `--overwrite`, `--only-dependencies`, `--include-test`, `--keep-tmp`, `--debug-symbols`, `--build-bottle`, `--skip-post-install`, `--skip-link`, `--as-dependency`, `--ignore-dependencies`, `--force-bottle`, `--bottle-arch`, `-i/--interactive`, `-g/--git`, `--cc`, `--formula`/`--cask`, `-n/--dry-run`, `-v/--verbose`, `-y/--no-ask`; `brew reinstall` shares install flags (manpage).
- **Ask mode is the default in 7.0.11**: install/upgrade prompt for confirmation before downloading ("Ask mode is the default"); suppress with `-y/--no-ask` or `HOMEBREW_NO_ASK=1`. A GUI MUST pass `-y` (it implements its own confirmation) or brew will hang on a TTY prompt.
- Bottle facts (docs Bottles + verified live JSON): a bottle is a "gzipped tarball of compiled binaries"; matched automatically at install when the bottle tag matches the OS/arch. Tag scheme = `arch_codename` (observed `arm64_golden_gate`; docs mention `arm64_tahoe`/`sequoia`). Bottle metadata in info JSON: `bottle.<stable|head>.rebuild`, `.root_url` (default `https://ghcr.io/v2/homebrew/core`), `.files.<tag>.{cellar,url,sha256}`; `cellar` `:any` means relocatable. `rebuild >= 1` means the bottle was updated without formula version change. The formula's own definition is stored inside the poured keg at `Cellar/<name>/<ver>/.brew/<name>.rb` (read-only inspection of exactly what was installed).
- Source-vs-bottle switching: `--build-from-source` (user), `pour_bottle?` DSL with `only_if:` presets (`:default_prefix`, `:clt_installed`; surfaced as `pour_bottle_only_if` in JSON), "any options specified" disables bottle use, `--force-bottle` overrides, `HOMEBREW_NO_BOTTLE` does **not** exist in the 7.x ENVIRONMENT section (old name; use `--build-from-source`). `HOMEBREW_NO_RELOCATE_BUILD_PREFIX` disables relocation (forces source). `HOMEBREW_NO_INSTALL_FROM_API` switches core/cask from API (JSON) installs back to git-checked-out taps — explains `Core tap: N/A` in `brew config`.
- Bottle fetching/inspection: `brew fetch --bottle-tag=TAG [--os=OS --arch=ARCH] [--all-platforms] [--deps] [--retry]` (verified flag text; actually fetching downloads files — mutating cache), `brew fetch --force` re-downloads. ghcr.io auth: `HOMEBREW_GITHUB_PACKAGES_TOKEN`/`HOMEBREW_GITHUB_PACKAGES_USER` (Bintray vars are gone — Bottles page no longer mentions Bintray); mirrors via `HOMEBREW_BOTTLE_DOMAIN`, `HOMEBREW_ARTIFACT_DOMAIN(_NO_FALLBACK)`, `HOMEBREW_API_DOMAIN`. Private tap bottles: use GitHub Packages creds (docs Bottles links "internal software delivery"; exact private-tap recipe UNVERIFIED). Provenance attestation: `HOMEBREW_VERIFY_ATTESTATIONS` (uses `gh`), `brew verify` command (`-j/--json`, `--bottle-tag`).
- After install: `HOMEBREW_NO_INSTALL_UPGRADE` (install won't upgrade outdated pkg), `HOMEBREW_NO_INSTALL_CLEANUP`, `HOMEBREW_NO_INSTALLED_DEPENDENTS_CHECK` (skips the dependents churn a GUI may want to control explicitly).

### 5. Cask lifecycle
- GUI feature: app install/update/remove, "clean remove (zap)".
- Commands: `brew install --cask <token>` (cask flags: `--adopt` take over pre-existing app, `--require-sha`, `--skip-cask-deps`, `--[no-]binaries`, `--language=xx`, `--appdir=…` and the full artifact-dir family `--prefpanedir`, `--fontdir`, … — manpage "Global Cask Options"); `brew uninstall --cask [--force] [--zap]` (verified: `--zap` "Remove all files associated with a cask. May remove files which are shared between applications."; `--force`: "Uninstall even if cask is not installed, overwrite existing files and ignore errors"); `brew reinstall --cask`. `--purge` is **invalid in 7.0.11** (verified: `Error: invalid option: --purge`) — do not offer it.
- `HOMEBREW_CASK_OPTS` appends options to every cask command; `HOMEBREW_FORBIDDEN_CASKS` refuses installs.
- Artifact model (docs Cask-Cookbook + observed `artifacts` JSON): `app`, `pkg` (installed via `/usr/sbin/installer`, **not sandboxed, may need admin password**), `dmg` handled via container, `binary`/`command_wrapper` → symlinks in `$(brew --prefix)/bin`, `suite`, `font`, `prefpane`, `stage_only`, completions, etc. `container {nested:, type: (:dmg,:pkg,:zip,…)}`. `uninstall` directives apply in fixed order (`early_script → launchctl → quit → signal → login_item → kext → script → pkgutil → delete → trash → rmdir`); `quit:`/`signal:` run during upgrade too. `zap` only via `brew uninstall --zap` (never automatic; `--force` allows zapping already-removed casks). Flight steps (`preflight_steps`…) are "structured, JSON-serialisable" — they surface in info JSON artifacts (observed `sudo: true` early_script for Wireshark's uninstall pkg).
- Status fields for UI: `auto_updates`, `version` (`:latest`), `deprecated`/`deprecation_reason` (preset reasons incl. `:discontinued` = "discontinued upstream"), `disabled`/`disable_reason`. Deprecated casks: warning, install proceeds; disabled casks: error, fails (docs Deprecating page). Discontinued/deprecated casks are removed from the tap one year after disable.
- sudo requirements: cask `pkg`/`installer`/`sudo: true` steps invoke `sudo`; `HOMEBREW_NO_SUDO` disables sudo calls; `SUDO_ASKPASS` lets an external (GUI) agent answer the password prompt — a GUI driving installs of pkg casks must handle or pre-arrange askpass.

### 6. Pinning, link/unlink, version switching
- `brew pin` / `brew unpin` (usage verified; note shown: dependents of pinned formulae "might not install or run correctly"; pinned auto-updating casks may self-update anyway). No JSON; pinned state readable via `list --json`'s `pinned_version` and info JSON `pinned`. GUI wired 2026-10-31: Pin/Unpin button in the package-page header plus a row context menu in every list section; commands run as `pin|unpin --formula|--cask <full_name>` (the kind flag disambiguates same-name formula/cask), and a successful pin re-reads the inventory so the Pinned section and Update buttons follow immediately.
- `brew link [--overwrite] [-f to link keg-only] [--dry-run]` / `brew unlink [--dry-run]` — `--dry-run` verified locally ("Would remove: /opt/homebrew/include/ace…"). A GUI can preview link changes safely.
- Version selection: **`brew switch` is gone** (no `switch` entry anywhere in the 7.x manpage; local `brew switch` falls through to generic usage text — treat as removed). Supported replacements per manpage/docs: installing versioned formulae (`node@22`, `mariadb@10.5` — present locally), `brew version-install` and `brew extract` (extract copies a version into a personal tap; both listed in `brew commands`), plus `link --HEAD`. Re-verified 2026-11-02: `brew commands` lists **no `switch` and no bare `versions`** (the earlier "versions present" note matched `version-install`/`--version` — retracted). Switch planning and `version-install` semantics: §27.
- keg-only formulae: `keg_only`/`keg_only_reason` in JSON; `linked_keg` null when unlinked; `optlinked_version` in `list --json` tracks the stable `opt/<name>` link. Docs page for using keg-only deps outside brew: `/How-to-Build-Software-Outside-Homebrew-with-Homebrew-keg-only-Dependencies`.

### 7. Taps
- GUI feature: repository manager.
- Commands (docs Taps + verified): `brew tap` (lists installed taps; `umputun/apps` observed; prints nothing when none), `brew tap <user>/<repo> [URL]` (mutating), `brew untap <user>/<repo>` (mutating; `-f` uninstalls its packages first), `brew tap --repair` (re-symlinks manpages/completions, fixes renamed branches — mutating but low-risk), `brew tap-info --installed --json` (verified).
- "List of external repos" (verified 2026-10-30): `brew tap` = plain text, one `user/repo` per line, **installed taps only** (API-mode core/cask absent; no `--json`). The GUI source is `brew tap-info --installed --json` → one object per tap. Official API taps give `name,user,repo,repository,path,installed:false,official:true,trusted,formula_names[],cask_tokens[]`; *tapped* repos add `formula_files,cask_files,command_files,remote,custom_remote,private,HEAD,last_commit,branch`. Filter external = `installed == true && official == false`. Local: 3 objects, 1 external — `umputun/apps` → `https://github.com/umputun/homebrew-apps`, 16 formulae / 2 casks, `trusted:false`, `branch:master`. `last_commit` is relative text ("2 days ago") — parse `HEAD` or re-derive via git if the GUI needs a real date.
- Per-package provenance without a tap query: cask/formula info JSON carries `tap` and `tap_git_head` (e.g. `umputun/apps/agterm` → `tap: "umputun/apps"`, `tap_git_head: 1391b96…`). Qualified names come from `brew list --formula|--cask --full-name`. One tap can host many items: `agterm` and `revmux` are two *casks* of the single tap `umputun/apps` (there is no `revmux/agterm` tap) — a `<word>/<word>` string in a listing is ambiguous unless the tap boundary is resolved.
- Repo naming: GitHub repos must be `homebrew-<repo>`; on-disk at `$(brew --prefix)/Library/Taps/<user>/homebrew-<repo>`. brew's own GitHub URL for `brew tap user/repo` is `https://github.com/<user>/homebrew-<repo>`; the two-argument form (`brew tap user/repo URL`) skips that assumption and accepts any git transport.
- GUI-side constraint (SwiftUI, verified 2026-10-30 by bisection against the HEAD build): the macOS sidebar `List(selection:)` is AppKit-backed and **silently stops hit-testing every row** when the selection binding/tag type is anything other than the shipped `BreweryCore.Section` — both an enum with associated values and a custom `String`-raw enum failed; `Section` works. The Taps pane is therefore a `Section` case (`matchesSection(.taps)` → false; `PackageList` never receives it) so sidebar rows keep the proven `.tag(section)` shape. Symptom if reintroduced: all rows dead, binding `.onChange` never fires, while window chrome (split-view collapse) still works.
- Cost (measured 2026-10-30): `brew tap-info --installed --json` = 2.1–2.2 s, 336,970 bytes — the size is the official API taps listing all 8684 formulae + 7816 cask tokens. The GUI therefore loads taps lazily (Taps pane) and never inside the inventory refresh. Key spelling: the commit is `"HEAD"`, not `"head"`.
- **`formula_names` / `cask_tokens` are qualified for cloned taps and bare for API taps** (live, verified): `umputun/apps` → `"umputun/apps/agterm"`, `homebrew/core` → `"ace"`. Matching inventory rows and displaying them both need the prefix stripped — the GUI keeps the raw strings on `TapInfo` and normalizes in `tapContents`.
- `formula_files` / `cask_files` / `command_files` are **arrays of `.rb` paths**, not counts (live: 2, 2, `[]` for `umputun/apps`). Decoding them as `Int` throws on real data.
- Text form without jq: `brew tap` (names only) and `brew tap-info --installed` (per-tap block: `Installed`/`Not installed`, `Untrusted`, counts, path+file count+size, `From: <remote>`, `HEAD:`, `last commit:`, `==> Formulae` / `==> Casks` lists). Untapped-but-known repos answer targeted queries (`brew tap-info homebrew/cask-versions --json` → `installed:false`, empty name lists), so "does this repo exist" is checkable pre-mutation (unused so far).
- Trust has two levels (verified): `brew trust --json=v1` on this machine lists `formulae: ["umputun/apps/revdiff"]`, `casks: ["umputun/apps/agterm","umputun/apps/revmux"]` while `tap-info` reports `umputun/apps` as `trusted:false` — item-level grants do not make the tap trusted. Flags: `brew trust --tap|--formula|--cask|--command`, `brew untrust --tap …` (both mutating the trust store, not the packages).
- `brew untap [user/repo …]`: `-f/--force` uninstalls the tap's formulae and casks first. Help text is the source here — a live untap was NOT run (needs explicit approval), so brew's refusal wording for a tap with installed items is UNVERIFIED locally; the GUI shows whatever stderr it gets.
- Trust model (docs Taps): "Code in a tap can run with your user's privileges." Fully-qualified install (`brew install user/repo/formula`) trusts that item; otherwise `brew trust --formula user/repo/formula` (a real 7.x command — present in `brew commands`). `trusted` field visible in tap-info JSON. Policy knobs: `HOMEBREW_FORBIDDEN_TAPS/_FORMULAE/_CASKS/_LICENSES`, `HOMEBREW_DISABLE_LOAD_FORMULA`.
- API mode interplay: core/cask taps are normally *not* on disk (`Core tap: N/A`); `brew tap --force` reinstalls core taps as git checkouts (docs flag text), or `HOMEBREW_NO_INSTALL_FROM_API=1` makes brew expect them. Taps' `formula_names`/`cask_tokens` come from the API even for untapped official repos (observed).
- A tap may shadow a core formula (use qualified names); "Dependencies of `homebrew/core` formulae cannot be replaced with formulae from other taps." `tap_migrations.json` redirects installs for migrated formulae (docs `/Migrating-A-Formula-To-A-Tap`; JSON exposure of migrations UNVERIFIED).
- Trust enforcement is visible in listings: `brew formulae` printed "Warning: Skipping umputun/apps because it is not trusted. Run `brew trust umputun/apps` to trust it." — untrusted tap contents are silently omitted from catalog queries, and the GUI should surface that warning rather than showing an unexplained gap. Trust store location (from `untrust` usage): `${XDG_CONFIG_HOME}/homebrew/trust.json`.

### 13. Exit codes & error reporting
- Verified/doc'd: `doctor`, `audit`, `missing`, `bundle check` exit non-zero when problems found ("useful for scripting"); `bundle cleanup` returns 1 if its prompt is declined ("prompts before removing anything unless `--force`"). Invalid flags/args error out early. General failure = non-zero exit; success = 0.
- Warnings vs errors: deprecated packages warn and proceed; disabled packages error and fail (docs lifecycle). `HOMEBREW_DEVELOPER=1` turns warnings into errors — a GUI should not inherit this from a user's shell; unset it explicitly.
- Verbosity: `-v/--verbose` and `-d/--debug` are **per-command post-name options** (manpage: "these options should appear after a command"); env-global equivalents `HOMEBREW_VERBOSE`, `HOMEBREW_DEBUG`. `-q/--quiet` per command. `HOMEBREW_NO_COLOR`/`NO_COLOR`/`HOMEBREW_COLOR` control ANSI codes — set `HOMEBREW_NO_COLOR=1` when capturing output, or strip ANSI. `HOMEBREW_VERBOSE_USING_DOTS` keeps long builds alive with periodic dots. `HOMEBREW_LOCK_CONTEXT` adds context to lock-contention errors — relevant when brew calls overlap.
- Long-running commands: install/build has no machine-readable progress protocol; a GUI must stream stdout+stderr line-wise, decide failure by exit code, and set `HOMEBREW_NO_AUTO_UPDATE`, `HOMEBREW_NO_ENV_HINTS` (suppresses "Adjust how often this is run with…" hint spam seen in verified output), `HOMEBREW_NO_ANALYTICS`, `HOMEBREW_NO_EMOJI` for clean capture. Concurrency knobs: `HOMEBREW_DOWNLOAD_CONCURRENCY` (auto = 2×cores), `HOMEBREW_MAKE_JOBS`, `HOMEBREW_CURL_RETRIES` (3).
- Homebrew's own code lifecycle (docs Deprecating page): deprecated CLI flags are hidden from `--help` and warn when used; disabled flags raise errors; removals happen at minor/major releases, never patch — so a GUI's flag allow-list should be re-verified against `--help` output at startup, not hard-coded forever.

### 14. brew bundle — Brewfile export/import (major GUI feature)
- GUI feature: "export my setup", reproducible install, machine migration, diff-able inventory snapshot.

### 26. Uninstalling installed packages (GUI action; verified 2026-11-02 against `brew uninstall --help` + brew's own Ruby source)

- Command: `brew uninstall --formula|--cask <qualified>` (kind flag disambiguates a formula/cask name clash, same posture as pin/trust). Synonyms `remove`/`rm` exist; the GUI uses `uninstall`.
- **No `-y`/`--yes`** in uninstall's flag set (verified via help, 2026-11-02): uninstall never shows the ask-mode prompt (ask covers install/reinstall/upgrade), so there is no TTY prompt to hang the GUI — unlike install/upgrade, which need `-y` (§77). Passing `-y` would be an invalid-option error.
- **Version scope**: brew's default keg set is `:default_kegs` — the linked/current version only (`cmd/uninstall.rb`); `-f/--force` is `:kegs` = **all installed versions**. For casks `--force` instead means "uninstall even if not installed, ignore errors" — the GUI exposes `--force` only as a formula multi-version button ("Remove all N versions"), never for casks.
- **Dependents refusal**: without `--ignore-dependencies`, brew fails uninstall when other installed packages depend on the target. Exact wording (`dependents_message.rb:26-38`): `Refusing to uninstall X because it is required by Y, which is currently installed. You can override this and force removal with: brew uninstall --ignore-dependencies X`. Casks get the same protection via `Cask::Uninstall.check_dependent_casks` unless `--ignore-dependencies` — the flag works for both kinds even though its help text names only formulae. GUI: surfaces the refusal verbatim + offers the override as a separate confirmed button.
- **Pinned refusal**: plain uninstall of a pinned package fails outright — `"<full_name> is pinned. You must unpin it to uninstall."` (formula: `uninstall.rb`; cask: `cask/uninstall.rb` `unpin_for_removal?`, which auto-unpins only under `--force`). GUI disables the Uninstall button while pinned (same posture as Update) and names the adjacent Unpin.
- **Autoremove side effect**: every successful uninstall runs `Cleanup.autoremove` unless `HOMEBREW_NO_AUTOREMOVE` is set (`cmd/uninstall.rb`; `HOMEBREW_AUTOREMOVE` is a no-op — autoremove is brew's default). Uninstalling X can silently remove formulae that were only installed as X's dependencies. GUI does not suppress it; the confirmation copy warns and the post-action inventory re-read shows what left.
- **Trust side effect**: uninstalling an item from a tap that is not tap-trusted removes the item's individual trust grant (`Homebrew::Trust.untrust!` in `cmd/uninstall.rb`). The model re-reads taps+trust after every uninstall anyway.
- `--zap` (cask "remove all files … may remove files which are shared between applications") stays out of the GUI until a scary-warning screen exists (§317: no dry-run, no exposed zap paths); plain cask uninstall removes only brew-tracked artifacts.
- GUI affordances shipped 2026-11-02: **Uninstall** button in the package-page header (installed packages; disabled while pinned) with a confirm alert carrying version scope + dependents + autoremove warnings and the two brew-faithful variant buttons; **Uninstall** in the row context menu (destructive role, last item) with a compact confirm alert; a `tapAction` banner in the list panes now shows running/failed state for all row-initiated mutations (uninstall, pin) — previously those errors were visible only on the detail page.

### 27. Switching a formula to a specific version (GUI action; verified 2026-11-02 against live `brew info` probes + brew's Ruby source: `dev-cmd/extract.rb`, `cli/named_args.rb`, `cmd/link.rb`, `cmd/unlink.rb`, `tap.rb`)

- **No `switch` command**: `brew switch`/`brew versions` are absent from 7.0.11 (`brew commands`; `brew switch --help` falls through to the generic command list). Version switching is extract+install, or keg relinking.
- **Versioned names don't resolve unless a tap defines them** (live 2026-11-02): `brew info --json=v2 wget@1.21.1` → `Error: No available formula with the name "wget@1.21.1".`; `brew info --cask iterm2@3.4.0` → `Error: Cask 'iterm2@3.4.0' is unavailable: No Cask with this name exists.` So plain `brew uninstall X && brew install X@V` always fails at the install step — some tap must materialize the `X@V` definition first. `brew extract` is what does that.
- **`brew extract [--version=V] [--force] <formula> <tap>`** (`dev-cmd/extract.rb`, a dev command — no HOMEBREW_DEVELOPER needed to *run* it, only to extract *into* core): source tap must be cloned on disk (`raise … unless source_tap.installed?`; `Tap#installed?` = `path.directory?` — on API-mode machines homebrew/core has no directory, so the GUI runs `brew tap homebrew/core` first). Destination refuses `homebrew/core`, `homebrew/cask`, and the source tap itself. Searches git history backwards for the version (shallow clone → odie telling the user `git fetch --unshallow`). Writes `<dest>/Formula/<bare-name>@<sanitized>.rb`, renames the class (`FooAT123`), and **strips bottle blocks** — the extracted formula builds **from source**. Version sanitization: `sub(/\D*(.+?)\D*$/,"\\1").gsub(/\D+/, ".")` (`2.0.14p1` → `2.0.14.1`); the GUI parses extract's `Writing formula … to:` path line for the exact name, with the sanitized fallback. `--force` overwrites an existing extracted definition (the GUI passes it; the confirm sheet covers the tap write).
- **Installed-keg resolution is rack-based** (`cli/named_args.rb` `resolve_kegs`): a versioned install lives at `Cellar/<name>@<version>/<version>`, so `brew link/unlink <name>@<version>` addresses that keg with no tap definition (qualified `tap/name@V` additionally filters by the keg's INSTALL_RECEIPT tap). `brew link` resolves `:latest_kegs` (highest keg in the rack — so a legacy multi-version `Cellar/<name>` keg cannot be pinned to its older keg; the GUI routes that case through extract instead); `brew unlink` resolves `:default_kegs` (the linked keg). Keg-only targets need `brew link --force` (its own help text).
- **GUI switch design**: relink when the target keg is installed (`brew unlink <linked family kegs>` → `brew link <target rack>`, nothing re-downloaded); extract+install when it isn't (`tap homebrew/core` if virtual → `extract --force --version=V <name> <dest-tap>` → `unlink` linked family kegs so install's symlinks don't collide → `install -y <dest-tap>/<name>@<V>`). The old keg stays installed but unlinked, so switching back is the instant relink. Destination tap comes from the installed-tap list (core/cask/source are brew-refused; the GUI says so and points at the Taps pane when the list is empty). Ask-mode `-y` applies to the install step only (extract/link/unlink have no prompt; §77 posture).
- **`brew version-install <formula>[@V] [V]`** is brew's own shorthand for the extract path (`cmd/version-install.rb` — a normal command, not dev-cmd; verified present in 7.0.11 `brew commands`): skips extract when some tap already defines `<name>@V` (`Formulary.factory` check), short-circuits when the current formula version already equals V, otherwise resolves a username (GitHub login → `User.current` → `$USER`), creates `<user>/homebrew-versions` **locally** via `tap-new --no-git` (no GitHub repo), runs `extract … --version=V` (no `--force`), then `install` — nested *without* `-y` — and prints "You are responsible for maintaining this … It will not receive any bugfix/security updates." It internally sets `HOMEBREW_DEV_CMD_RUN=1` ("pretend we've run a dev command"). The GUI runs extract+install explicitly instead of calling version-install: destination tap is user-chosen rather than forced to `<user>/homebrew-versions`, the install carries `-y` (version-install's nested install would block on an ask-mode prompt inside a GUI subprocess — the app neither sets nor strips `HOMEBREW_ASK`), and the plan sheet shows the exact commands.
- **Casks have no supported version switching** — no versioned cask installs, `extract` is formula-only. GUI: no switch button on cask rows, caption states the gap.
- GUI affordances shipped 2026-11-02: ⇄ icon button on switchable version-history rows (`arrow.triangle.swap`; hidden when already linked / cask / no destination), "linked" vs "installed" chips, `SwitchVersionSheet` confirm sheet listing the exact brew commands + source-build and core-clone warnings, running/failed state via the existing `tapAction` banner (`switchingToVersion`/`relinkingTo` labels), taps auto-loaded whenever the version-history section is on.

### 28. Live progress streaming & SIGINT cancellation (GUI posture; verified 2026-11-10 against brew's `brew.rb` + a zsh repro under Foundation `Process`)

- **Capability**: show brew's output live and offer Cancel during the long mutations (`install -y`, `update`, `upgrade -y`, `tap …`, the §27 switch steps) — commands unchanged; the stream is plain stdout+stderr lines thanks to the fixedEnv posture (§13), no ANSI to strip.
- **Cancel semantics**: SIGINT (Foundation `Process.interrupt()`) is the Ctrl-C path — `brew.rb:22` `std_trap = trap("INT") { exit! 130 }`, verified live (cancelled fake brew exited 130 in ~0.4 s). brew documents no rollback; partial work can be real, so a cancelled action reloads taps + inventory (and the GUI says so in the failure banner). Distinguish *cancelled* from *brew refused*: refusals still don't trigger the reload.
- **Grandchildren outlive the exit — EOF is not a completion signal** (measured 2026-11-10): brew's INT trap exits ruby, but the children it spawned (git, curl; in the repro, a backgrounded `sleep 10 &`) keep running with inherited copies of the pipe's write ends, so the pipe's EOF lags the exit by the grandchild's whole lifetime — `availableData`/`readDataToEndOfFile` hangs exactly that long (10 s repro; the app's 10 s stall was this, not signal loss). A read loop keyed on *process exit* + two silent 120 ms poll windows (hard-capped 2 s past exit) returns in ~0.4 s with brew's full output intact. Related asymmetry: terminal Ctrl-C reaches the whole process group; `kill(pid, SIGINT)` reaches brew only — grandchildren may finish their current step on their own.
- **macOS poll quirk** (measured): `poll()` reports `POLLIN` **together with** `POLLHUP` when a writer closes with bytes still unread — drain `POLLIN` first; treating HUP as EOF first silently drops the final line (that is how a cancelled child's last output went missing during development).
- **Thread placement** (measured): the blocking poll loop must not run inside a cooperative-pool `Task` — it occupies a pool thread for the whole brew run and starves every other Task; under a concurrent test suite the cancel watchdog arrived ~10 s late. Run it on the global dispatch queue.
- **Signal-mask red herring, retired**: spawning from a thread with SIGINT blocked — even the main thread — still delivers SIGINT to the child within ~50 ms (`kill()` returns 0 and the child's trap runs immediately); no `pthread_sigmask` juggling around `process.run()` is needed or wanted.
- **Script-side note** (for fakes/tests): bash 3.2 (the system `/bin/sh`) defers INT traps until the foreground builtin finishes; zsh and brew's Ruby run them on arrival. Cancel tests use zsh.
- **Progress-bar rendering**: brew redraws its bar with bare `\r` → the splitter treats bare `\r` (and `\r\n` as one) as terminators; consecutive bar frames fold to the latest in the GUI buffer (capped 300 lines); `==>`-prefixed message lines never fold.

All rename/migration keys are **dicts** — an earlier hand-written test fixture used an array `formula_renames` + `tap_migrations`/`tap_git_head` keys; that shape is not in the payload and the fixture was corrected.
- **Per-entry mirrors**: formula entries carry `aliases` (e.g. go ← golang) and `oldnames`; the top-level `formula_aliases` mirrors the per-entry lists exactly (0/8723 mismatches 2026-11-12) — decode either form only, not both. Cask entries carry `names` (all product names incl. localized — 208 casks have >1); the per-entry cask `renames` key is **artifact filename pairs** (`uninstall:`/pkg-path renames), not token renames — no search value, deliberately not decoded.
- **Cask `desc`** (verified 2026-11-10): present for 5188/7823 casks ("Web browser", "Network protocol analyzer") — decoded; casks without one behave like tap entries (desc nil → no subtitle, no desc-contains tier). The Install pane's 400 tier now reaches casks.
- **Migration direction** (live 2026-11-12): `formula_tap_migrations` targets are always `homebrew/cask` (formula became a cask), `cask_tap_migrations` always `homebrew/core` — so the alias term attaches to the **opposite-kind** row. Destination value is `"homebrew/cask"` (name kept) or `"homebrew/cask/app-engine"` (name changes too). 72/81 migrations keep the same name → the destination already matches by name, no entry point needed. 8 targets are packages the manifest no longer lists (renamed away twice / deleted) → unresolvable, skip.
- **Scoring rule (GUI decision, not a brew fact)**: alias terms score their tier −100, so a direct name hit (or a tie with one) always outranks them and shows no hint; only otherwise-unmatched rows surface, captioned "aka X" / "renamed from X" / "moved from X". Consequence: `openssl` → openssl@4 shows no hint (alias is also a 900 prefix hit); `golang` → go shows "aka golang". The Installed pane's filter shares the same index with a contains-only rule (typing an old name finds the installed row; no caption — the row already shows its real name).

## Gaps / no supported way

- **No versioned JSON schema.** Info/list/outdated JSON may gain fields without notice; parse defensively (ignore unknown keys, expect nulls — e.g. `versions.head` is null or `"HEAD"`, `linked_version` null).
- **No JSON for deps/uses/leaves/search/commands/config/doctor/missing/upgrade/install**; text-parsing or API reconstruction only. No supported reverse-dependency JSON for *installed* state beyond inverting `installed[].runtime_dependencies`.
- **No progress/event protocol**: no machine-readable status stream for long builds; only line-text + exit codes + logs dir. No way to cancel cleanly mid-build through brew itself (GUI must SIGINT and then run `brew` lock cleanup per Common-Issues — UNVERIFIED specifics).
- **No dry-run for pin/unpin/link-side-effects beyond the link/unlink/cleanup/autoremove/install/upgrade `-n` flags listed above**; no dry-run for `uninstall --zap` (cannot preview which zap files would be deleted — the zap list is not exposed by info JSON in 7.x; `artifacts.uninstall`/`zap` are authoring directives, not "resolved paths" — UNVERIFIED whether JSON exposes them).
- **No read-only version switch for an installed formula** (`switch` removed; every route mutates — relink an installed keg or extract+install, §27 where the GUI ships both; `version-install`'s maintenance caveat applies to extracted installs).
- **No supported Mac App Store management** in brew 7.x (the old `brew mas` is gone; casks redirect via `:moved_to_mas`) — a GUI cannot manage App Store apps through brew.
- **No read-only bottle availability query for arbitrary OS/arch tags** without either downloading (`brew fetch --bottle-tag`, mutating cache) or reading the formula's own `bottle.files` JSON (only lists published tags; `brew unbottled` is a maintainer command — UNVERIFIED usability).
- **No transaction/rollback API** — a failed install leaves partial state; only `brew doctor`-style detection afterward.
- **`brew cask`, `--purge`, `HOMEBREW_NO_BOTTLE`, `brew commands --json`, `deps --json` are removed** — legacy recipes/blogs describe them; a 7.x GUI must not. Same for `brew bundle restore` (absent from 7.0.11's verified subcommand list) and `brew bottle`'s legacy `--all`/`--tap` flags.
- **`brew update-if-needed` behavior is undocumented/unverifiable from the CLI** (silent, no usage output) — the GUI's "refresh" action should use plain `brew update`.
- **Brewfile has no JSON**: `bundle list` is plain text; parsing/diffing Brewfiles is GUI-side work.
- **No changelog/news in brew** — no command, no JSON field, no formulae.brew.sh endpoint; version history requires GitHub (commits-by-path for core, releases API for upstream notes) or local tap git. See §21.
